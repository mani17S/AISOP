## 1. Executive Summary

The AISOP Artificial Intelligence (AI) Subsystem serves as the core reasoning engine for security investigation assistance. It assists Security Operations Center (SOC) analysts by automating tedious analytical tasks:
- Correlating evidence across process, network, file, and registry artifacts.
- Mapping observed indicators and attacker behaviors to the MITRE ATT&CK knowledge base.
- Generating investigation hypotheses with transparent confidence scoring.
- Formulating actionable, non-destructive next steps for incident responders.
- Generating role-tailored incident reports (Executive, Technical, Detection Engineering).

## 2. Core Architectural Principles

1. **Lightweight Protocol Abstraction (ADR-001):**
   AISOP core business logic never couples to proprietary LLM frameworks (e.g. LangChain, LangGraph, LlamaIndex) or vendor SDKs. All AI interactions flow through a runtime checkable `LLMProvider` Protocol.
2. **Local-First Reference Implementation:**
   The reference deployment is fully local and zero-cost, backed by a local Ollama instance running open-weights models (`llama3.1:8b` or `mistral:7b`) with zero telemetry or cloud leakage.
3. **No Autonomous Containment or Destructive Actions:**
   In accordance with the AISOP Charter, the AI subsystem is strictly **advisory and analytical**. It never executes containment actions, process kills, firewall changes, or data deletion.
4. **Deterministic Testing:**
   All AI adapters are verified using deterministic in-memory mock transports (`httpx.MockTransport`), requiring zero live daemon or GPU availability in CI pipelines.
5. **Streaming Deferred to Frontend:**
   Streaming generation is deferred to Phase 4 (Investigation Dashboard). Phase 2 backend pipelines consume complete, validated JSON or text responses.
6. **The Untrusted Data Axiom:**
   All telemetry attributes, commands, filenames, registry keys, and retrieved knowledge chunks are treated as untrusted data. Prompts strictly isolate evidence inside XML tags with boundary defense.
7. **Three-Tier Epistemic Claim Grounding:**
   Claims generated by the model are decomposed into Reference Existence (Tier 1 deterministic set check), Information Containment (Tier 2 rule-based matching), and Logical Justification (Tier 3 human analyst evaluation). A claim is never marked proven solely because its cited UUID exists.

## 3. Subsystem Component Hierarchy

```
AISOP AI Subsystem
├── Provider Layer (P2-H1) [Implemented]
│   ├── Protocol: LLMProvider
│   ├── Data Contracts: LLMRequest, LLMResponse, TokenUsage, ProviderHealthResponse
│   ├── Exceptions: LLMError hierarchy
│   ├── Reference Adapter: OllamaProvider (async httpx + tenacity)
│   └── Manager: get_llm_provider() factory
├── Knowledge & Retrieval Layer (P2-H2 / P2-H3) [Implemented]
│   ├── MITRE ATT&CK Ingestion & Document Chunker
│   ├── Direct OllamaEmbedder (768-dim nomic-embed-text)
│   └── pgvector HNSW Cosine Semantic Search (ADR-002)
├── Threat Intelligence Correlation Layer (P2-H4 Hist. / TI-3B) [Implemented]
│   ├── RFC1918 / Loopback PrivateNetworkShield
│   ├── Local Cache-backed Feed Lookup Engine
│   └── Resilient ThreatIntelOrchestrator
└── SOC Reasoning & Investigation Engine (P2-H4 Curr. / P2-H5 Hist. Tasks 2.1–2.5) [Implemented]
    ├── Canonical Serializer & Forensic Hasher: compute_context_sha256 (AISOP-CJSON-1.0)
    ├── Multi-Event Context Assembly: InvestigationContextBuilder with deterministic pruning
    ├── Defensive Prompt Engineering: InvestigationPromptBuilder with XML untrusted data isolation
    ├── Structured Response Parser: InvestigationResponseParser with length-truncation detection
    ├── Output Guardrails & Claim Grounding: InvestigationOutputValidator (3-Tier Grounding)
    ├── End-to-End Orchestration: InvestigationPipelineService
    └── REST Endpoint: POST /api/v1/investigations/synthesize
├── Role-Tailored Report Synthesizer (P2-H6 — Historical Alias: P2-H5 Candidate) [Implemented & Verified]
│   ├── Executive Brief Generator
│   ├── SOC Technical Incident Response Report Generator
│   ├── Detection Engineering / Playbook Synthesizer
│   ├── Deterministic Markdown Formatter & Table Injection Defense
│   └── Endpoints: POST /api/v1/reports/synthesize & /reports/format
└── Phase 2 Capstone Review & Pipeline Consolidation (P2-H7) [Implemented & Verified]
    ├── End-to-End Capstone Integration Harness (test_phase2_capstone.py)
    ├── Live PostgreSQL 17 + pgvector Tier 3 Certification (port 5433)
    └── Phase 2 Closeout Report (682 Passing Tests)
```
