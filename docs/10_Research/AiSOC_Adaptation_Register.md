# AiSOC to AISOP Adaptation Register

AiSOC (`D:\AiSOC`, MIT code licence; rule content under its own licences) was used as an architectural **reference**. No AiSOC source file was copied: each row states the concept observed in AiSOC source, what AISOP implemented differently, and where. AiSOC is a multi-tenant, streaming (Kafka/Redis/Postgres) platform; AISOP is a single-node, batch, explainable-first system, so only the *ideas* transfer. Labels: IMPLEMENTED / PARTIAL / PROPOSED / NOT ADOPTED.

| # | AiSOC source (verified by reading) | Concept | AISOP implementation | Deliberate difference | Status |
|---|---|---|---|---|---|
| 1 | `services/fusion/app/services/attack_chain_grouper.py` (STRONG / SPECIFIC / WEAK link tiers; weak links must not weld stories) | Typed, strength-ranked links decide what a relationship may do | `backend/app/modules/evidence/independence.py: entity_link_strength` (+ `STRONG_ENTITY_TYPES`, `SPECIFIC_ENTITY_TYPES`); `correlation/correlator.py: correlate` (weak links never merge multi-evidence groups, only attach a lone observation as context) | AiSOC allows a weak link inside one detection rule; AISOC-style tiers are also used as the **corroboration rule of the sufficiency gate** (not in AiSOC) | IMPLEMENTED |
| 2 | `attack_chain_grouper.py` `_TACTIC_ORDER`, `_ESCALATION_MIN_STAGES = 3` | Kill-chain ordering and severity escalation at three stages | `correlator.py: STAGE_ORDER, CATEGORY_TO_STAGE, ESCALATION_MIN_STAGES`, `Incident.stages/escalated` | Escalation counts only the strongly linked core | IMPLEMENTED |
| 3 | `services/fusion/app/services/deduplicator.py` (`fingerprint()` over entity fields; Redis window) | Fingerprint de-duplication before correlation | `independence.py: cluster_evidence` (same digest, identical content, **near-duplicates within 2 s**); `correlator.py: build_clusters` | No Redis; near-duplicate collapse and "same raw record" collapse are additions; unverifiable digests never merge | IMPLEMENTED |
| 4 | `services/fusion/app/services/correlator.py` (`correlation_key`: entity + tactic, narrowing instead of widening when fields are missing) | Correlation key must narrow, not widen | Same principle in `correlate`: no link without a shared entity; missing fields produce no link; `unknown` is never a shared value | AiSOC groups by one key in Redis; AISOP builds an explicit link graph with reasons shown in the report | IMPLEMENTED |
| 5 | `services/fusion/app/services/provenance.py` (connector / OCSF provenance from the ingest envelope) | Keep provenance on every normalized event | `correlation/normalize.py: normalize_records` (SHA-256 of every raw record on every event; rejected records kept with digest); reuses ADR-007 adapters | AiSOC carries connector ids; AISOP carries a content digest | IMPLEMENTED |
| 6 | `services/fusion/app/services/asset_context.py` (asset context enrichment) | Attribute network-only records to an asset | `normalize_records(assets=…)`: IP to host, labelled `host_source=asset_inventory`, weak link only | Minimal dictionary, no CMDB integration | PARTIAL |
| 7 | `services/fusion/app/services/narrative.py` (deterministic, LLM-free correlation narrative) | The analyst report must be useful without an LLM | `correlation/report.py: render_incident_report`; `workflow.analyze` (no LLM path) | Report prints the sufficiency verdict and reason codes in plain language | IMPLEMENTED |
| 8 | `services/agents/app/investigator/ledger.py` (investigation ledger; append-only in the database) | Record each investigation step durably | `correlation/ledger.py: Ledger, verify_chain` (hash-chained, tamper-evident) | AiSOC relies on database append-only; AISOP chains hashes. Not persisted yet | IMPLEMENTED (in memory); persistence PARTIAL |
| 9 | `services/agents/app/confidence/verdict_gate.py` (verdict gate; fail-open by design) | A gate between evidence and conclusion | `ai/guardrails/sufficiency_gate.py` + `gated_generation.py` | **Opposite policy:** AISOP's gate is deterministic and **fails closed**; it runs before the model rather than after | IMPLEMENTED (different design) |
| 10 | `packages/aisoc-detections`, `services/fusion/app/services/windowed_detection.py` (detections carrying ATT&CK tags, evaluated by a rule engine) | Deterministic rules map telemetry to ATT&CK | `correlation/mitre.py: RULES, map_techniques` (six rules, each with evidence and a stated limitation; vendor assertions kept separate) | No Sigma import, no third-party rule content (licence-clean) | IMPLEMENTED (6 rules) |
| 11 | `services/fusion` pipeline order: ingest -> normalize -> fuse/correlate -> agents | Spine ordering of the workflow | `correlation/workflow.py: analyze, run_workflow` | Batch function instead of Kafka consumers | IMPLEMENTED |
| 12 | `packages/aisoc-benchmark` (baseline-floor scorecard) | Evaluate against a baseline, report negatives | `modules/evaluation/sufficiency_evaluator.py` (gate-on/off ablation, per-class metrics, coverage-risk, kappa) | Labels are owner-authored; metrics pending labels | PARTIAL |
| 13 | Kafka/Go ingest, OCSF mapping in Go, multi-tenancy, UEBA, connectors (~100), agents framework | Production streaming platform | none | Out of scope for a single-node academic system | NOT ADOPTED |
| 14 | `services/api/.../endpoints/investigations.py: get_timeline`, `get_run` | Read a stored investigation as separate timeline/status views | `GET .../multisource/{section}` (`cases.py`, `service.section_view`) | Sections are views of one stored document with a stale-evidence flag; case-role RBAC instead of tenant scoping | IMPLEMENTED |
| 15 | same file: `/bundle`, `/replay`, idempotent `close_investigation` | Idempotent repeatable operations and an exportable record | Fingerprint idempotency in `service.start` (200 reused, `force` to re-run); no replay or bundle | Idempotence by evidence fingerprint; no export bundle | PARTIAL |
| 16 | `agents/app/investigator/ledger.py` (best-effort writes) | Durable step record | Ledger head and steps inside the stored result; audit write is **fail-closed** (`PersistenceFailed`, no result returned) | Opposite of best-effort: an unrecorded investigation is not shown | IMPLEMENTED (persistence PARTIAL: audit-row document) |
