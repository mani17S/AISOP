## 1. Launch Policy Statement

AISOP is a local-first, privacy-preserving cybersecurity engineering platform designed to operate with zero mandatory recurring service costs.

**AISOP MUST NOT be publicly deployed, hosted, published, or exposed to the public Internet until every launch gate defined in this document has been independently implemented, verified, and explicitly approved by the Project Owner.**

Development previews and CI/CD tests do NOT constitute authorization for public release.

---

## 2. Mandatory Launch Gates

### Gate 1: Custom Domain & DNS Ownership
- [ ] A dedicated sovereign domain (e.g. `aisop.dev`, `aisop.io`, or `aisop-security.org`) or explicitly approved custom subdomain must be legally acquired.
- [ ] DNS must be configured via a secure, privacy-respecting provider (e.g. Cloudflare Free DNS or deSEC.io).
- [ ] Strict DNSSEC must be activated and verified.
- [ ] TLS certificate renewal automation (Let's Encrypt / ACME) must be established and tested.
- [ ] Zero reliance on high-risk, abuse-flagged dynamic DNS domains (e.g. DuckDNS, Afraid.org).

### Gate 2: Professional Brand Identity & Favicon
- [ ] An official, professional SVG and PNG favicon must be implemented.
- [ ] Favicon must represent genuine AISOP brand identity across desktop, mobile, and browser tabs.
- [ ] No generic emoji icons (e.g. 🛡️ or 🤖) or AI-generated stock placeholders may be used as the site icon.

### Gate 3: Branding & Third-Party Cleanup
- [ ] All "Made with AI", "Generated by AI", or template-generator watermarks must be eradicated.
- [ ] All development placeholders, dummy lorem ipsum, and temporary test alerts must be purged.
- [ ] Legally required open-source third-party attribution (MIT, Apache 2.0, BSD notices) must be verified and preserved in a dedicated `/about` or `/licenses` view.

### Gate 4: Legally Compliant Privacy Policy
- [ ] A production Privacy Policy page (`/privacy`) must be deployed.
- [ ] The policy must accurately disclose:
  - Local-first telemetry handling (data remains on user premises).
  - Exact nature of processed security event logs (Sysmon, network metadata, authentication attempts).
  - Zero third-party telemetry sharing or external model training.
  - Hashed API token and session storage boundaries.
  - Applicable regulatory rights (GDPR, CCPA, local data privacy charters).
- [ ] Generic boilerplate or copy-pasted legal templates are strictly prohibited.

### Gate 5: Technically Grounded Terms & Conditions
- [ ] A comprehensive Terms and Conditions page (`/terms`) must be deployed.
- [ ] Terms must explicitly address:
  - Permitted use for authorized security operations and internal network defense.
  - Strict prohibition against unauthorized offensive scanning or malicious usage.
  - Human-in-the-loop requirement: AISOP findings are advisory; human analyst oversight is required before executing remediation.
  - Limitation of liability regarding automated AI suggestions and false positives.

### Gate 6: Security Verification & Threat Hardening
- [ ] Full regression test suite passing:
  - 100% pass rate on BOLA/IDOR regression tests (`test_case_bola_security.py`).
  - 100% pass rate on full offline backend suite (`1,144+ passed`).
  - 100% pass rate on frontend component and XSS security tests (`npm test`).
  - Clean TypeScript compilation (`tsc --noEmit`) and Vite production bundle (`vite build`).
- [ ] Server-side security headers verified:
  - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; frame-ancestors 'none';`
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  - `Referrer-Policy: strict-origin-when-cross-origin`
- [ ] Token-bucket rate limiting verified against volumetric and credential brute-force attacks.
- [ ] Zero sensitive credentials, API keys, or raw JWT secrets exposed in client bundles or console output.

### Gate 7: Design Constitution Compliance
- [ ] Impeccable design audit executed (`/impeccable audit`).
- [ ] Zero prohibited visual patterns:
  - No purple or generic blue-purple gradients.
  - No pill-shaped buttons.
  - No emoji interface icons.
  - No em dashes in copy.
  - Zero fabricated metrics, fake customer reviews, or simulated threat counts.
- [ ] Information density and typography tuned for professional SOC operational clarity.

### Gate 8: Formal Project Owner Approval
- [ ] Final end-to-end review conducted by the Project Owner.
- [ ] Explicit written authorization issued before DNS pointer activation.

## 3. Post-Launch Ongoing Invariants

Once deployed:
1. All model inference must remain locally operated via Ollama unless an explicitly authorized cloud backend is sanctioned.
2. In-memory and session-scoped credential boundaries must be maintained.
3. No automated containment or destructive actions may be triggered without explicit human analyst intervention.
